# Prompt Forge — 기능 명세 (v1.0)

> "내 프롬프트는 99%의 확률로 안전한가?"에 대한 답을 주는 도구.

## 사용자

- 1인 개발자 및 프롬프트 엔지니어
- 자신의 API Key를 넣어 로컬에서 즉시 사용

## 제약 조건

- DB 없음 — localStorage 기반
- 백엔드 없음 — 클라이언트 사이드에서 LLM API 직접 호출
- 사용자 API Key는 브라우저 로컬 스토리지에만 저장
- 프롬프트 템플릿 변수 문법: Mustache 스타일 `{{variable}}`

---

## P0 (필수) — 없으면 출시 불가

### F01. 프롬프트 에디터

- 설명: Mustache 변수(`{{variable}}`)를 지원하는 프롬프트 작성 영역
- 사용자 스토리: 프롬프트 엔지니어로서, 변수가 포함된 프롬프트 템플릿을 작성하고 싶다
- 입력: 프롬프트 텍스트 (Mustache 변수 포함)
- 출력: 파싱된 변수 목록 자동 추출, 변수 입력 필드 자동 생성
- 예외: 닫히지 않은 `{{` — 경고 표시

### F02. Stress Test (일관성 테스트)

- 설명: 동일 프롬프트를 N회 반복 실행하고 결과 일관성을 수치로 측정
- 사용자 스토리: 프롬프트 엔지니어로서, 내 프롬프트의 출력이 얼마나 안정적인지 알고 싶다
- 입력: 프롬프트, 모델 선택, 반복 횟수(N), 변수값
- 출력: N개의 응답 목록, 일관성 점수
- 일관성 측정:
  - **Primary — 코사인 유사도**: N개 결과 간 임베딩 코사인 유사도 평균 계산
    - ≥ 0.95: 매우 일관적
    - 0.7 ~ 0.95: 보통
    - < 0.7: 불안정
  - **Secondary — LLM-as-Judge** (옵션): 유사도가 낮을 때 또는 사용자 선택 시 활성화. "N개의 응답이 의미적으로 동일한 의도를 전달하는가?" 판별
- 예외: API 호출 실패 시 해당 회차 skip 처리, 성공 건수 기준으로 점수 산출

### F03. Unit Testing (기대값 비교)

- 설명: 변수 세트별로 기대 결과와 실제 LLM 응답을 비교
- 사용자 스토리: 프롬프트 엔지니어로서, 다양한 입력에 대해 프롬프트가 기대한 결과를 내는지 검증하고 싶다
- 입력: 프롬프트 템플릿, 테스트 케이스 목록 `[{ variables, expected, mode }]`
- 출력: 케이스별 Pass/Fail, 전체 성공률
- 비교 모드 (다중 지원):
  - **Semantic** (기본값): LLM-as-Judge로 의미적 일치 판단. 예: "수도가 서울입니다" vs "대한민국의 수도는 서울" → Pass
  - **Contains**: 기대값 문자열이 응답에 포함되는지 확인
  - **Regex**: 정규표현식 패턴 매칭
  - **Exact**: 정확히 일치
- 예외: 비교 모드 미선택 시 Semantic 기본 적용

### F04. API Key 설정

- 설명: 프로바이더별 API Key 입력 및 저장
- 사용자 스토리: 사용자로서, 내 API Key를 안전하게 입력하고 여러 모델을 사용하고 싶다
- 입력: 프로바이더(Anthropic, OpenAI, Google), API Key
- 출력: localStorage에 저장, "이 키는 브라우저 로컬 스토리지에만 저장됩니다" 안내 표시
- 지원 모델:
  - Anthropic: Claude Sonnet, Claude Haiku 등
  - OpenAI: GPT-4o, GPT-4o-mini 등
  - Google: Gemini Pro, Gemini Flash 등
- 예외: 키 미입력 시 해당 프로바이더 모델 비활성화

## P1 (중요) — 첫 번째 릴리즈에 포함 권장

### F05. Model Benchmarking (모델 비교)

- 설명: 동일 프롬프트를 여러 모델에 동시 투입하고 결과 비교
- 사용자 스토리: 프롬프트 엔지니어로서, 같은 프롬프트에 대해 어떤 모델이 가장 적합한지 비교하고 싶다
- 입력: 프롬프트, 모델 복수 선택, 변수값
- 출력: 모델별 응답, 응답 시간, 토큰 사용량 비교 차트
- UI: 모델별 응답을 나란히 배치 + Recharts로 성능 지표 시각화
- 예외: API Key가 없는 프로바이더의 모델은 선택 불가

### F06. 결과 히스토리

- 설명: 테스트 결과를 localStorage에 자동 저장
- 사용자 스토리: 사용자로서, 이전 테스트 결과를 다시 확인하고 싶다
- 입력: 테스트 실행 결과 (자동)
- 출력: 최근 20건의 결과 목록 (타임스탬프, 테스트 유형, 요약 점수)
- 사이드바에서 클릭하여 상세 결과 확인 가능
- 예외: 20건 초과 시 가장 오래된 항목 자동 삭제

### F07. JSON Export

- 설명: 테스트 케이스와 결과를 JSON 파일로 내보내기
- 사용자 스토리: 사용자로서, 테스트 결과를 팀에 공유하거나 기록으로 남기고 싶다
- 입력: 내보낼 결과 선택
- 출력: `.json` 파일 다운로드 (프롬프트, 변수, 결과, 통계치 포함)

## P2 (선택) — 이후 반복에서 추가

### F08. Auto-Optimizer (프롬프트 개선)

- 설명: 실패 케이스를 분석하여 프롬프트 개선안 제안
- 사용자 스토리: 프롬프트 엔지니어로서, 실패 원인을 파악하고 자동으로 개선된 프롬프트를 받고 싶다
- 입력: 실패한 테스트 케이스 목록, 원본 프롬프트
- 출력: 개선된 프롬프트 (diff 표시), 개선 이유 설명
- LLM에게 실패 패턴을 분석시키고 개선 프롬프트를 생성

### F09. 프롬프트 저장/관리

- 설명: 자주 쓰는 프롬프트를 이름을 붙여 저장
- 입력: 프롬프트 이름, 템플릿
- 출력: 사이드바 프롬프트 목록에 추가

### F10. JSON Import

- 설명: 내보낸 JSON 파일을 불러와 테스트 케이스 복원
- 입력: `.json` 파일 업로드
- 출력: 프롬프트 및 테스트 케이스 자동 세팅

## UI 구조

```
┌─────────────┬──────────────────────────────────────────┐
│  Sidebar    │  Main Content                            │
│             │                                          │
│  저장된      │  [프롬프트 에디터]                         │
│  프롬프트    │  ┌──────────────────────────────────────┐ │
│  목록       │  │ 프롬프트 텍스트 입력                    │ │
│             │  │ {{variable}} 자동 감지                 │ │
│  ──────     │  └──────────────────────────────────────┘ │
│             │                                          │
│  최근       │  [Tabs]                                   │
│  히스토리    │  ┌─────────┬────────────┬──────────┐      │
│             │  │ Runner  │ Benchmark  │Analytics │      │
│             │  └─────────┴────────────┴──────────┘      │
│             │                                          │
│             │  Runner: Stress Test / Unit Test 실행     │
│             │  Benchmark: 모델별 비교 차트               │
│             │  Analytics: 일관성/성공률 통계              │
│             │                                          │
├─────────────┴──────────────────────────────────────────┤
│  [Settings] API Key 설정 (모달 또는 별도 페이지)         │
└────────────────────────────────────────────────────────┘
```

## 비기능 요구사항

- 다크 모드 기본 지원 (Shadcn UI 내장)
- 반응형 레이아웃 (모바일 고려하되 데스크톱 우선)
- LLM API 호출 시 로딩 상태 표시
- API 호출 실패 시 에러 메시지 표시 (키 만료, rate limit 등)
